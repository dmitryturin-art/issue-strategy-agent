# GitHub Follow-up Draft

Используй этот skill, когда в обсуждении появилась конкретная доработка, которую стоит зафиксировать как backlog item или GitHub issue.

## Что делать

1. Быстро прочитай:
   `docs/agent/tracking.md`, `docs/agent/github.md`, при необходимости `ROADMAP.md`
2. Проверь, это:
   - просто заметка в roadmap
   - уже полноценная задача для GitHub issue
   - draft issue, если создать issue сейчас нельзя или рано
3. Подготовь:
   - короткий заголовок
   - проблему или контекст
   - ожидаемое поведение / результат
   - при необходимости черновые шаги реализации
4. Все тексты по умолчанию пиши на русском языке.
5. Если задача еще не создается в GitHub, явно пометь ее как draft.

## Принцип

- Не оставляй полезный follow-up только в чате.
- Не заводи issue на сырое brainstorming без сигнала пользователя.
- Если задача влияет на развитие продукта, проверь, нужна ли запись и в `ROADMAP.md`, и в GitHub issue.

## Когда читать references

- Для шаблона issue открой `references/template.md`.
