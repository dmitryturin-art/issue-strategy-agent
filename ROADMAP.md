# Roadmap

Здесь фиксируются запланированные улучшения. Текущая версия — MVP.

---

## v1.1 — Голосовые сообщения

**Задача:** Принимать голосовые сообщения и транскрибировать их в текст перед передачей в LLM.

**Реализация:**
- Скачать `.ogg` через Telegram Bot API
- Транскрибировать через [OpenAI Whisper API](https://platform.openai.com/docs/api-reference/audio/createTranscription) (или локальный whisper)
- Добавить переменную `WHISPER_MODEL` / `WHISPER_BASE_URL` в конфиг
- Поддержать голосовые как в прямых сообщениях боту, так и в replied message

**Текущий статус:** заглушка — бот отвечает "Голосовые сообщения пока не поддерживаются."

---

## v1.2 — Мультирепозиторий

**Задача:** Один бот — несколько GitHub репозиториев.

**Реализация:**
- Пользователь указывает проект ключевым словом или названием: `@bot задача для leash-system: ...`
- LLM определяет проект из контекста, если явно не указан
- Если проект неоднозначен — бот уточняет: "Вы имеете в виду `leash-system` или `bell-sensors`?"
- Маппинг `проект → owner/repo` хранится в конфиге или в БД
- Команда `/setrepo project owner/repo` для администраторов группы

## v1.2.1 — Память проектов / контекст репозитория

**Задача:** Дать боту минимальную долговременную память о проектах, чтобы LLM лучше понимала домен, стек, ограничения и смысл задач.

**Реализация:**
- Хранить краткий профиль проекта в отдельном файле или реестре
- Для каждого проекта описывать: `project_key`, `repo`, краткое описание продукта, стек, доменные сущности, архитектурные ограничения
- Подмешивать этот контекст в `system`/`user` prompt при `is_issue`, `preview` и `edit`
- Позже перевести память в машиночитаемый формат для мультирепозитория

**Зачем:**
- Меньше галлюцинаций по домену
- Лучше понимание legacy-ограничений
- Более точные issue-превью без длинных ручных пояснений в каждом сообщении

## v1.3 — Inline-кнопки для approve/edit

**Задача:** Добавить inline-кнопки под preview вместо reply-текста.

**Реализация:**
- `[✅ Создать issue]` — approve
- `[✏️ Изменить]` — запрашивает текст правки следующим сообщением
- `[❌ Отмена]` — удаляет preview, не создаёт issue
- Реализовать через `aiogram.types.InlineKeyboardMarkup` + callback handlers

## v2.0 — Мультигрупповой режим / мультитенантность

**Задача:** Один инстанс бота обслуживает несколько Telegram-групп с разными конфигурациями.

**Реализация:**
- Таблица `group_config(chat_id, repo, allowed_labels, ...)`
- Команда `/config` для настройки группы администратором
- Изоляция данных между группами
