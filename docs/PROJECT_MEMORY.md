# Project Memory

Минимальная память по проектам, с которыми работает issue-bot.
Этот файл нужен как человекочитаемый источник контекста для промптов, настройки мультирепозитория и будущей "памяти" агента.

## `kimg` / `pavodok_map`

### Репозиторий
- GitHub: `dmitryturin-art/pavodok_map`
- Внутренний ключ проекта: `kimg`
- Основной продукт: `pavodok_map`

### Краткое описание
Production Flutter-приложение для мониторинга гидропостов и раннего обнаружения паводков, ориентированное в первую очередь на web.

Система агрегирует данные по гидропостам, визуализирует их на интерактивной карте, показывает телеметрию по каждому объекту, отображает фото с камер и журнал тревог.

### Основной пользовательский сценарий
Оператор открывает карту, видит состояние всех постов по цветам и кластерам, переходит в карточку конкретного поста, анализирует графики уровней и связанные параметры, затем при необходимости смотрит фотоархив и алерты.

### Стек и ключевые библиотеки
- Flutter `3.9.2`
- Dart
- `flutter_map` + OpenStreetMap
- `flutter_map_marker_cluster`
- `syncfusion_flutter_charts`
- `http`
- `shared_preferences`
- `toastification`
- `audioplayers`

### Источники данных / API
- `GET /api/devices` — список групп и гидропостов
- `GET /api/dat?id=...` — исторические ряды и данные дашборда
- `GET /g/index1.php?id=...` — галерея изображений
- `GET /api/pm23hrv` — legacy-авторизация
- Текущий `url_server`: `https://api2.techmon.ru`

### Архитектурное состояние as-is
- Проект production и legacy одновременно
- Основная логика находится в `lib/pages/*`
- Состояние управляется через `setState()`
- Используется `global.dart` с глобальными мутабельными переменными
- DI и нормального state management нет
- Важнее аккуратно встраивать изменения в существующую логику, чем перепридумывать архитектуру с нуля

### Ключевые экраны и модули
- `login.dart` — авторизация
- `public_map.dart` — главная карта, список и кластеры гидропостов
- `public_map_history2.dart` — исторические графики
- `grafana_dashboard.dart` — расширенная карточка гидропоста
- `gallery.dart` и `gallery_details.dart` — фотоархив
- `alarms_window.dart` — тревоги
- `dashboard_service.dart` и `dashboard_data.dart` — слой данных дашборда

### Доменные сущности
- Гидропост / устройство: `DeviceMAP`
- Маркер карты: `DeviceMarker`
- Временные точки графиков: `DataPoint`
- Alarm-события
- Пороги тревог
- Hints / атрибуты устройства

### Сильные стороны продукта
- Карта с цветовой индикацией статусов
- Кластеризация объектов
- Тултипы и карточки гидропостов
- Графики телеметрии с пороговыми зонами
- Галерея кадров с камер
- Тревожные уведомления
- Отдельный dashboard-экран

### Технические риски и ограничения
- Большие файлы
- Слабая модульность
- Отсутствие тестов
- Глобальное состояние
- Legacy-подход к авторизации
- Риски по поддерживаемости и безопасному рефакторингу

### Какой тон должен учитывать агент
- Это не greenfield
- Нельзя без отдельной задачи предлагать радикальный переписывательский рефакторинг
- Предпочтительны точечные и совместимые изменения
- При формулировке issue полезно учитывать продуктовый контекст: гидропосты, карта, telemetry, alarms, gallery, dashboard

### Что может пригодиться в будущих промптах
- Проект связан с мониторингом паводков и гидропостов
- Основная UX-ось: карта → карточка поста → графики → фото → тревоги
- Любые задачи вокруг карты, кластеров, телеметрии, графиков, камер и алертов с высокой вероятностью относятся к этому проекту
