# Typical Workflow

## Обычный цикл работы по задаче

1. Прочитать релевантный контекст:
   `docs/WORKLOG.md`, `ROADMAP.md`, при необходимости `docs/ARCHITECTURE.md` и `docs/PROJECT_MEMORY.md`.
2. Внести изменения в код.
3. Прогнать быструю локальную проверку:
   `PYTHONPYCACHEPREFIX=/private/tmp/issue-bot-pycache venv/bin/python -m py_compile app/*.py`
4. Если менялось поведение бота, перезапустить локальный процесс:
   остановить текущий `python -m app.main`, затем снова выполнить `venv/bin/python -m app.main`.
5. Проверить сценарий в Telegram на живом сообщении, если задача про поведение бота.

## Предпочтения по архитектуре поведения

- Для явных и критичных сценариев использовать deterministic-ветки.
- Для разговорных и неявных формулировок использовать гибридный подход с LLM-assisted routing.
- Не отдавать целиком все управление модели там, где простое правило надежнее и предсказуемее.
