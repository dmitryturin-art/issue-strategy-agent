# Self-Improvement Rules

## Зачем это нужно

Цель не в том, чтобы без конца разрастать агентские инструкции, а в том, чтобы уменьшать повторяющуюся ручную работу, экономить токены и быстрее находить нужный контекст.

## Когда стоит предлагать новое улучшение для агента

Если в проекте регулярно повторяется хотя бы один из сценариев:
- приходится снова и снова искать один и тот же operational context
- часто повторяются одни и те же команды и проверки
- регулярно нужен один и тот же шаблон issue, draft, prompt или workflow
- появляется устойчивый класс задач, для которых отдельный skill или микро-инструкция заметно ускорят работу

## Что предпочтительнее добавлять сначала

1. Небольшой markdown-файл в `docs/agent/`, если нужно сохранить знания или workflow.
2. Обновление `AGENTS.md` как индекс, если появился новый важный раздел.
3. Новый skill, если задача реально повторяемая, многошаговая и от него будет заметная экономия контекста и времени.

## Когда стоит предлагать новый skill

Skill уместен, если:
- сценарий повторяется во многих сессиях
- у него есть устойчивая последовательность шагов
- нужен специфический контекст, который не хочется каждый раз перечитывать целиком
- есть шанс сократить количество открываемых файлов и объем лишнего текста

Примеры для этого проекта:
- skill для triage обращений к боту
- skill для оформления GitHub issue/draft issue по итогам обсуждения
- skill для локального перезапуска и smoke-check бота

## Ограничения

- Не предлагать новый skill ради мелочи, которую проще держать в одном markdown-файле.
- Не раздувать память проекта дублирующими документами.
- При добавлении новых инструкций лучше делать маленькие тематические файлы, чем один большой свод.

## Практическое правило

Если во время работы становится заметно, что агент уже второй или третий раз делает одну и ту же подготовительную процедуру, стоит предложить:
- новый файл в `docs/agent/`
- новый skill
- или установку подходящего существующего skill из доступных источников, если это упростит работу в будущем

## Правило про найденный рабочий путь

Если что-то сначала не работало, а потом удалось найти устойчивый рабочий способ, его стоит сохранить в память проекта без отдельного напоминания от пользователя.

Особенно это касается:
- команд запуска и перезапуска
- способов доступа к GitHub
- credential flows
- обходов ограничений окружения
- коротких operational playbook для повторяющихся действий

Если решение влияет на будущие сессии, оно должно попасть как минимум в один из вариантов:
- `docs/agent/*.md`
- локальный skill
- `AGENTS.md` как индекс на новый раздел
