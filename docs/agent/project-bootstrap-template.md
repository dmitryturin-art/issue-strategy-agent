# Project Bootstrap Template

## Как использовать

Скопируй этот шаблон в новый проект и на его основе разверни минимальную агентную память.

Минимальный набор:
- `AGENTS.md`
- `docs/agent/session-start.md`
- `docs/agent/communication.md`
- `docs/agent/runtime.md`
- `docs/agent/workflow.md`
- `docs/agent/tracking.md`

Потом уже по необходимости добавляй:
- `docs/agent/commands.md`
- `docs/agent/github.md`
- `docs/agent/debugging.md`
- `docs/agent/self-improvement.md`
- `.codex/skills/`

---

## 1. AGENTS.md

```md
# Project Instructions

Используй этот файл как короткий индекс, а не как единственный источник контекста.

## Как читать проектные инструкции

- Быстрый старт новой сессии: `docs/agent/session-start.md`
- Общие правила работы и язык: `docs/agent/communication.md`
- Локальное окружение и команды запуска: `docs/agent/runtime.md`
- Типовой рабочий цикл: `docs/agent/workflow.md`
- Правила фиксации follow-up задач: `docs/agent/tracking.md`
- Частые рабочие команды проекта: `docs/agent/commands.md`
- Типовые сценарии отладки: `docs/agent/debugging.md`
- Правила самоулучшения и работы со skills: `docs/agent/self-improvement.md`
- Локальные project-specific skills: `.codex/skills/`

## Базовые принципы

- Общение с пользователем и все user-facing тексты по умолчанию только на [УКАЖИ ЯЗЫК].
- Для явных и критичных сценариев предпочитай deterministic-логику.
- Для неявных формулировок используй LLM-assisted routing там, где это реально полезно.
- Если по итогам обсуждения появляется конкретное улучшение, не оставляй его только в чате: фиксируй в backlog проекта.
```

## 2. docs/agent/session-start.md

```md
# Session Start

## Что открыть в новой сессии за 30 секунд

1. `AGENTS.md`
2. `docs/agent/runtime.md`
3. `docs/agent/workflow.md`
4. `[УКАЖИ ОСНОВНОЙ ЖУРНАЛ ИЗМЕНЕНИЙ]`
5. `[УКАЖИ ROADMAP ИЛИ АНАЛОГ]`

## Что быстро вспомнить

- Общение с пользователем и user-facing тексты по умолчанию только на [УКАЖИ ЯЗЫК].
- Точка входа проекта:
  `[УКАЖИ КОМАНДУ ЗАПУСКА]`
- Перед изменениями в логике полезно прогонять:
  `[УКАЖИ КОМАНДУ БЫСТРОЙ ПРОВЕРКИ]`

## Если задача уже понятна по типу

- `[SKILL ИЛИ ФАЙЛ ДЛЯ ПЕРЕЗАПУСКА/ПРОВЕРКИ]`
- `[SKILL ИЛИ ФАЙЛ ДЛЯ ОТЛАДКИ]`
- `[SKILL ИЛИ ФАЙЛ ДЛЯ BACKLOG / ISSUE DRAFT]`
```

# Communication Rules

## Язык

- Все общение с пользователем вести на [УКАЖИ ЯЗЫК].
- Все backlog items, issue drafts, roadmap entries и user-facing тексты писать на [УКАЖИ ЯЗЫК], если пользователь не просил другое.

- Писать коротко, по делу и без лишней бюрократии.

1. Прочитать релевантный контекст:
   `[СПИСОК ОСНОВНЫХ ФАЙЛОВ]`
2. Внести изменения в код.
3. Прогнать быструю локальную проверку:
   `[УКАЖИ КОМАНДУ]`

   `[УКАЖИ КОМАНДУ ИЛИ ПРОЦЕДУРУ]`

   `[УКАЖИ, КАК ИМЕННО]`

## 6. docs/agent/tracking.md

```md
# Tracking Rules

## Когда фиксировать follow-up

Если в обсуждении появляется конкретное улучшение, изменение поведения, UX-доработка, архитектурный follow-up или техдолг:

1. Записать это в `[ROADMAP ИЛИ АНАЛОГ]`, если это влияет на развитие проекта.
2. Создать issue / ticket, если задача уже достаточно конкретна.
3. Если issue нельзя создать прямо сейчас, подготовить draft issue.

## Ограничения

- Не заводить issue на сырое brainstorming без сигнала от пользователя.
- Перед созданием задачи проверять, нет ли дублей.
```

## 9. docs/agent/self-improvement.md

```md
# Self-Improvement Rules

## Когда стоит улучшать агентную систему

Если в проекте регулярно повторяется хотя бы один сценарий:
- снова и снова ищется один и тот же operational context
- повторяются одни и те же команды
- часто нужен один и тот же шаблон issue, draft, prompt или workflow

## Что добавлять сначала

1. Небольшой markdown-файл в `docs/agent/`
2. Обновление `AGENTS.md` как индекса
3. Новый локальный skill, если сценарий реально повторяемый и многошаговый
```

## Как обновлять этот шаблон по ходу дела

Обновляй bootstrap-шаблон, если:
- нашелся более удобный минимальный набор файлов
- выяснилось, что какой-то файл почти никогда не нужен
- появился более удачный паттерн для skills
- стало ясно, как еще сильнее сократить лишнее чтение контекста

Этот файл должен эволюционировать вместе с практикой, а не быть “замороженной документацией”.
