# Tracking Rules

## Когда фиксировать follow-up

Если в обсуждении появляется конкретное улучшение, изменение поведения, UX-доработка, архитектурный follow-up или техдолг, который имеет смысл отслеживать вне текущего чата:

1. Записать это в `ROADMAP.md`, если это влияет на среднесрочное направление продукта или новые возможности.
2. Также создать GitHub issue, если задача уже достаточно конкретна для разработки и ее нужно отслеживать в репозитории.
3. Если GitHub issue нельзя создать прямо сейчас, подготовить готовый draft issue и явно указать, что его еще нужно завести вручную или отдельным действием.

## Что обычно идет и в roadmap, и в issue

- Улучшение intent routing через LLM
- Доработки UX бота для неоднозначных команд
- Follow-up по надежности, логированию, тестам, деплою и правам
- Архитектурные улучшения, которые не должны потеряться после текущей сессии

## Ограничения

- Не заводить issue на сырое brainstorming без явного сигнала от пользователя, что это нужно трекать.
- Перед созданием issue быстро проверить `ROADMAP.md`, `docs/WORKLOG.md` и текущий контекст, чтобы не плодить дубли.
- Заголовки issue делать конкретными и ориентированными на действие.
